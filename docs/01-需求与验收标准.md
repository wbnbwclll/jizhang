# 语音记账 App —— 需求分析与验收标准（v0.1 基线）

> 用途：作为「项目概述与需求分析」「功能清单与验收标准」两章的底稿；后续开发完成后按第 4 章逐条打勾，作为最终验收证据索引。
> 本文档只定义"做什么、做到什么程度算过"，不涉及具体实现代码。

---

## 1. 项目概述

| 项 | 内容 |
| --- | --- |
| 产品名称 | 语音记账（VoiceLedger） |
| 形态 | Android 原生 App，Kotlin + Jetpack Compose + Room |
| 目标用户 | 有日常记账习惯但"懒得打字"的个人用户，尤其是通勤、排队、饭后等双手不便操作的场景 |
| 使用场景 | ① 饭后在手机上按住说话"昨天中午吃饭花了 28 块 5"，确认后入账；② 出差打车"打车 32"，自动归到交通；③ 月末翻账单，按月份筛选、搜索"打车"、改正一条金额 |
| 一句话价值 | 说一句话就能记账，识别、解析、入账全在一屏内完成，且全程离线可用（AI 解析为可选增强） |

### 1.1 要解决的问题

1. 传统记账 App 需要 3～5 次点击 + 键盘输入才能记一笔，高频场景下用户放弃记账。
2. 云语音识别类方案需要联网，隐私敏感且弱网下不可用。
3. 大模型直接写库容易"幻觉记账"（金额、日期编造），必须由用户确认。

### 1.2 本期范围边界（明确不做）

- 不做多账本、多账户、资产/负债、转账、报销。
- 不做银行卡/微信/支付宝账单自动导入。
- 不做云同步、登录、多设备。
- 不做预算提醒、图表报表（列为 P1，不进本期验收）。
- 不做 iOS / 小程序 / Web 端。

## 2. 功能需求

### 2.1 用户故事

| 编号 | 用户故事 | 优先级 |
| --- | --- | --- |
| US-01 | 作为用户，我按住麦克风说一句话，就能看到识别出的文字和解析出的账单草稿 | P0 |
| US-02 | 作为用户，我在解析结果里能改金额、分类、日期、备注，确认后才写入账本 | P0 |
| US-03 | 作为用户，我不方便说话时可以打字，同样走 AI 解析 | P0 |
| US-04 | 作为用户，我能按月查看账单、搜索关键字、修改和删除某一条 | P0 |
| US-05 | 作为用户，我关掉 App 再打开，之前记的账一条不少 | P0 |
| US-06 | 作为用户，断网时我依然能记账 | P0 |
| US-07 | 作为用户，我希望能看到本月花了多少、各类别占比多少 | P1（本期不验收） |

### 2.2 功能清单

| 编号 | 模块 | 功能点 | 说明 | 优先级 |
| --- | --- | --- | --- | --- |
| F-01 | 语音输入 | 按住说话录音 | 首次使用请求 RECORD_AUDIO 权限；按下开始录音，松手结束 | P0 |
| F-02 | 语音输入 | 端侧离线识别 | 传统深度学习小模型（ONNX 推理，模型随 APK 资源或首启下载），输出中文文本 | P0 |
| F-03 | 语音输入 | 识别中间态与失败处理 | 录音中显示波形/计时；<3 秒静音或空结果给出明确提示 | P0 |
| F-04 | AI 解析 | 自然语言 → 结构化账单 | 调用 DeepSeek（`deepseek-chat`，JSON 输出）抽取：方向、金额、分类、商户、备注、发生时间 | P0 |
| F-05 | AI 解析 | 相对时间归一化 | "昨天""上周五""中午"换算为具体日期时间 | P0 |
| F-06 | AI 解析 | 结果校验 | 金额必须 >0 且 ≤ 100 万；分类必须落在固定枚举内，否则归"其他"；无金额则判定为"无法记账" | P0 |
| F-07 | AI 解析 | 离线规则兜底 | 无网络 / 接口超时 / 返回非法 JSON 时，用本地正则抽取"数字 + 元/块"，按关键词映射分类，并标注"离线解析" | P0 |
| F-08 | 记账确认 | 草稿确认卡片 | 解析结果以可编辑表单呈现（金额、分类、日期时间、备注），用户点"确认入账"才落库 | P0 |
| F-09 | 记账确认 | 手动新建 | 不经过语音/AI，直接填表单记账 | P0 |
| F-10 | 账单列表 | 按月浏览 | 顶部月份选择器，默认当月；显示当月条数与合计 | P0 |
| F-11 | 账单列表 | 关键字搜索 | 在备注/商户/分类中模糊匹配 | P0 |
| F-12 | 账单列表 | 编辑 | 点击条目进入编辑，保存后列表与合计立即更新 | P0 |
| F-13 | 账单列表 | 删除 | 支持滑动或长按删除，二次确认 | P0 |
| F-14 | 数据 | 本地持久化 | Room 数据库，进程被杀 / 重装前数据不丢 | P0 |
| F-15 | 设置 | API Key 配置 | Key 不硬编码在源码中，从本地配置读取，可更换、可清空 | P0 |
| F-16 | 设置 | 模型管理 | 展示离线 ASR 模型状态（未下载/已就绪/加载失败），支持重新下载或重载 | P1 |
| F-17 | 统计 | 分类占比、月度趋势 | 本期不实现 | P1 |

### 2.3 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 离线可用 | 除 AI 解析外，录音、识别、列表、增删改查在飞行模式下全部可用 |
| NFR-02 | 性能 | 10 秒语音松手后 ≤3 秒出识别文本（中端真机）；AI 解析 ≤5 秒；列表 500 条滚动无明显卡顿 |
| NFR-03 | 稳定性 | 断网、接口 4xx/5xx、返回非法 JSON、录音被来电中断，均不得崩溃或 ANR |
| NFR-04 | 隐私 | 音频不上传、不落盘（仅在内存中处理）；账本数据仅存本机；日志不打印金额明细与 Key |
| NFR-05 | 密钥安全 | 仓库中不出现真实 API Key，仅提供 `local.properties.sample` 占位示例 |
| NFR-06 | 兼容性 | Android 8.0（API 26）及以上，至少 1 台真机或模拟器验证通过 |
| NFR-07 | 可访问性 | 所有可点击控件有 contentDescription；深色模式下文字与背景对比度可读 |

### 2.4 数据模型（草案，供建表说明使用）

```
transactions
  id            INTEGER PK AUTOINCREMENT
  amount_cents  INTEGER NOT NULL          -- 以"分"存储，避免浮点误差
  direction     TEXT NOT NULL             -- EXPENSE / INCOME
  category      TEXT NOT NULL             -- 固定枚举，见下
  merchant      TEXT NULL
  note          TEXT NULL
  occurred_at   INTEGER NOT NULL          -- 毫秒时间戳
  source        TEXT NOT NULL             -- VOICE / TEXT / MANUAL
  raw_input     TEXT NULL                 -- 原始识别/输入文本，便于回溯
  parser        TEXT NOT NULL             -- AI / LOCAL_RULE / MANUAL
  created_at    INTEGER NOT NULL
  updated_at    INTEGER NOT NULL

drafts（可选，或仅存内存）
  id, amount_cents, direction, category, merchant, note, occurred_at,
  confidence, raw_input, status(PENDING/CONFIRMED/DISCARDED)

settings
  key TEXT PK, value TEXT                 -- 如 api_key（加密存储）、asr_model_ready
```

分类枚举：
- 支出：餐饮、交通、购物、居住、娱乐、医疗、教育、人情、其他
- 收入：工资、兼职、红包、理财、其他

### 2.5 技术与工具选型（含理由与风险）

| 层 | 选型 | 理由 | 主要风险 / 应对 |
| --- | --- | --- | --- |
| 客户端 | Kotlin + Jetpack Compose | 声明式 UI，语音录音/权限/状态联动代码量小 | Compose 版本与 AGP 需对齐，锁定 BOM |
| 存储 | Room | 官方 ORM，编译期校验 SQL，便于写建表说明 | 无 |
| 语音识别 | 端侧 ONNX 小模型（如 sherpa-onnx + 中文 Paraformer/SenseVoice 小模型；备选 Whisper-tiny、Vosk 中文模型） | 完全离线、无第三方账号、模型可替换 | 模型体积较大、首次加载慢、低端机 RTF 可能 >1；先在真机测 RTF 再定模型，必要时换更小模型 |
| 结构化解析 | DeepSeek `deepseek-chat` + JSON 输出模式，temperature=0 | 中文口语理解好、价格低、JSON 模式免解析歧义 | 网络依赖、偶发非法 JSON、密钥泄露；用本地正则兜底 + BuildConfig 注入 + 严格 JSON 校验 |
| 兜底 | 本地正则 + 关键词映射 | 断网时核心功能不降级为"不可用" | 准确率有限，界面上明确标注来源 |
| 开发工具 | TRAE（编码/调试/文档）+ DeepSeek API（应用运行时） | 满足作业工具要求 | 过程留痕见第 4 章证据索引 |

关于密钥：Android 端把 Key 打包进 APK 存在被反编译提取的风险，本期采用 `local.properties → BuildConfig` 的方式保证"不入库、可替换"，并在报告"已知问题"中如实说明；后续改进方向是加一层轻量代理服务。

## 5. 已知风险与假设

| 编号 | 风险 | 影响 | 当前应对 | 后续改进 |
| --- | --- | --- | --- | --- |
| R-01 | 端侧 ASR 模型体积大、低端机识别慢 | 首启慢、识别超时 | 选小参数量中文模型；先测 RTF 再定稿；加载态可取消 | 模型按需下载、量化压缩 |
| R-02 | 中文口语识别准确率不足 | 金额识别错误 | 金额识别后强制用户确认；草稿可编辑 | 增加数字纠错规则、金额二次校验 |
| R-03 | DeepSeek 接口不稳定或返回非法 JSON | 解析失败 | 严格 schema 校验 + 本地正则兜底 | 加缓存与重试退避 |
| R-04 | API Key 打进 APK 可被反编译 | 密钥泄露 | Key 不入库、可随时作废；报告如实说明 | 增加服务端代理 |
| R-05 | 相对时间解析（"上周五"）边界错误 | 记账日期偏移 | 固定"以设备当前时区与时间为基准"，AI prompt 中显式传入当前时间 | 增加日期边界用例测试 |

假设：
- 用户设备为 Android 8.0+，具备麦克风；
- 演示与验收在可联网环境完成一次 AI 解析，离线能力单独验证；
- DeepSeek 账号额度足够完成开发自测。
